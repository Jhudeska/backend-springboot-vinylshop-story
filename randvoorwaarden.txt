2. Niet-functionele requirements
Deze eisen gaan niet over wat de applicatie doet, maar bijvoorbeeld over gebruiksgemak, beveiliging en prestaties.

Nr.	Requirement	Type
NF1	De applicatie moet eenvoudig te gebruiken zijn voor medewerkers zonder technische kennis.	Niet-functioneel
NF2	Een medewerker moet binnen 3 seconden een album kunnen vinden.	Niet-functioneel
NF3	De applicatie moet alleen toegankelijk zijn voor geautoriseerde gebruikers.	Niet-functioneel
NF4	De applicatie moet onderscheid maken tussen gebruikers met verschillende rechten.	Niet-functioneel
NF5	De applicatie moet gegevens consistent opslaan zodat relaties tussen albums, artiesten, genres en publishers niet verloren gaan.	Niet-functioneel
NF6	De applicatie moet beschikbaar zijn tijdens de openingstijden van de winkel.	Niet-functioneel
NF7	De gebruikersinterface moet overzichtelijk zijn en geschikt zijn voor dagelijks gebruik door medewerkers.	Niet-functioneel

Voor jouw opdracht zou ik bijvoorbeeld NF1 t/m NF5 gebruiken. Die zijn duidelijk en goed te verdedigen.

5. Relaties
Dit is het belangrijkste gedeelte van je klassendiagram.

Uit de tekst:

"Een publisher heeft meerdere albums uitgegeven maar een album hoort maar bij één publisher."

Dus:

Publisher 1 -------- 0..* Album

Een publisher kan meerdere albums hebben, maar een album heeft één publisher.

De tekst zegt:

"Een album kan van meerdere artiesten zijn, maar een artiest kan ook meerdere albums hebben uitgebracht."

Dat is een many-to-many relatie:

Artist 0..* -------- 0..* Album

De tekst zegt:

"Een album heeft maar één genre, maar een genre kan bij meerdere albums horen."

Dus:

Genre 1 -------- 0..* Album

Voor voorraad:

Album 1 -------- 1 Inventory

Een album heeft één voorraadregistratie.

7. Nog beter: UML-versie
Als je bijvoorbeeld PlantUML gebruikt, kun je het veel makkelijker tekenen:

@startuml

class Album {
    - id: int
    - name: String
    - releaseYear: int
    - price: double
    - cover: String
}

class Artist {
    - id: int
    - name: String
}

class Genre {
    - id: int
    - name: String
}

class Publisher {
    - id: int
    - name: String
}

class Inventory {
    - id: int
    - stock: int
    - sold: int
}

class Employee {
    - id: int
    - name: String
    - username: String
    - password: String
    - role: String
}

Publisher "1" -- "0..*" Album
Genre "1" -- "0..*" Album
Artist "0..*" -- "0..*" Album
Album "1" -- "1" Inventory

@enduml

Let vooral op deze vier relaties
Publisher 1  ───────  0..* Album

Genre     1  ───────  0..* Album

Artist    0..* ────── 0..* Album

Album     1  ──────── 1 Inventory
